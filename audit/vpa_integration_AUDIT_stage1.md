## 3. Exact JSONL Schemas

### Stability rows

Each stability JSONL row has these fields:

```json
{
  "mode": "stability",
  "example_id": "string",
  "position": 0,
  "prefix_token_ids": [1, 2, 3],
  "shard_ids": ["shard_0000", "shard_0001"],
  "shard_token_ids": [10, 11],
  "vote_counts": {"10": 1, "11": 1},
  "majority_token_id": 10,
  "num_shards": 2
}
```

Notes:

- `shard_ids` and `shard_token_ids` are mandatory and order-aligned.
- JSON object keys are strings, so integer token ids in `vote_counts` become string keys when written to JSONL and read back through `json.loads`.
- `majority_token_id` is computed by plurality. Ties follow first occurrence in shard order.

### Validity rows

Each validity JSONL row has these fields:

```json
{
  "mode": "validity",
  "example_id": "string",
  "target_id": "string",
  "position": 0,
  "target_prefix_token_ids": [1, 2, 3],
  "target_token_id": 10,
  "shard_ids": ["shard_0000", "shard_0001"],
  "shard_token_ids": [10, 11],
  "vote_counts": {"10": 1, "11": 1},
  "majority_token_id": 10,
  "num_shards": 2
}
```

Notes:

- `target_prefix_token_ids` is the prefix used when asking shards for the next token under a target/validity rollout.
- `target_token_id` is the desired target token for this position.
- `shard_ids` and `shard_token_ids` are mandatory and order-aligned.

## 4. Assumptions Made

- `example_id` and `target_id` are strings so they can represent source line ids, dataset ids, or future stable artifact ids.
- `position` is zero-based within the exported generated-token horizon.
- Token ids are integer tokenizer ids.
- `num_shards` must equal `len(shard_ids)` and `len(shard_token_ids)`.
- JSONL is the initial artifact format for inspection and small smoke runs.
- A later exporter will decide how to map real VPA examples and validity targets onto these row schemas.
